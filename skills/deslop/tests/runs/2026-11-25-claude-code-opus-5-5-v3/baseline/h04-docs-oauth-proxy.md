Many of our products are built on open source software, and we release a lot of our own work as open source too. It's especially satisfying when we get to contribute to another organization's open source project. [oauth2\_proxy](https://github.com/bitly/oauth2_proxy) (formerly google\_auth\_proxy) is a [Bitly](https://bitly.com/) program, written in [Go](https://golang.org/), that lets a web service authenticate users through their OAuth2 provider accounts, so the service doesn't need its own authentication code. That suited the internal [18F Hub](https://18f.gsa.gov/2014/12/23/hub/), a site generated by [Jekyll](http://jekyllrb.com/) that has no authentication logic.

The [General Services Administration (GSA) is a Google Apps for Government customer](http://googleforwork.blogspot.com/2011/07/gsa-has-gone-google.html), and we serve the Hub with the [Nginx web server](http://nginx.org/). That made it easy to set up Nginx and oauth2\_proxy to authenticate 18F team members and other GSA guests without touching the Hub code.

The public-facing Hub is an Nginx `server` block. Its `proxy_pass` directive forwards requests to oauth2\_proxy, which listens on `localhost:4180`. oauth2\_proxy then sends authenticated requests on to `localhost:8080`, a second Nginx `server` block that serves the pre-generated Jekyll site:

```
server {
    listen 443 ssl spdy;
    server_name hub.18f.gov;
    include ssl/star.18f.gov.conf;

    location /logo.png {
        alias /home/ubuntu/18f-hub/_site/assets/images/logo-18f-oauth.png;
    }

    location / {
        proxy_pass http://127.0.0.1:4180/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Scheme $scheme;
        proxy_connect_timeout 1;
        proxy_send_timeout 30;
        proxy_read_timeout 30;
    }
}

server {
    listen 127.0.0.1:8080;
    server_name hub.18f.gov;
    port_in_redirect off;
    error_page 404 /404/index.html;

    location / {
        ssi on;
        root /home/ubuntu/hub/_site;
        index index.html api.json;
        default_type text/html;
        set $authenticated_user $http_x_forwarded_email;
        set $access_token $http_x_forwarded_access_token;
    }
}
```

This worked well for 18F, with one catch: not every government agency uses Google Apps. We wanted guests from other agencies to be able to reach our internal Hub, or to run a Hub of their own. Our plan was to use 18F's [MyUSA](https://18f.gsa.gov/2015/05/18/myusa/) as the [OAuth2 authentication provider](http://oauth.net/articles/authentication/). But the Hub had no authentication code of its own, so how would we switch it to MyUSA?

Because Bitly had made oauth2\_proxy open source, I could read the code, figure out how it worked, fork it, and build a prototype that used MyUSA as the OAuth2 provider. Next, [I contacted the oauth2\_proxy maintainer](https://github.com/bitly/google_auth_proxy/issues/65), Jehiah Czebotar, for feedback and to ask whether he'd accept [a generalized OAuth2 provider interface](https://github.com/bitly/google_auth_proxy/pull/77) into the main `bitly/oauth2_proxy` repository. Once that interface was merged, Jehiah also let me add [the MyUSA provider](https://github.com/bitly/google_auth_proxy/pull/79) to the main repository, which means any oauth2\_proxy user can now authenticate with MyUSA. The interface helped people outside 18F and Bitly too: another developer used it to add [LinkedIn as an OAuth2 provider](https://github.com/bitly/google_auth_proxy/pull/84), and Jehiah added [GitHub as a provider](https://github.com/bitly/oauth2_proxy/pull/98).

That was a real milestone for 18F's work in the open source community, and for MyUSA especially, but we kept going. We wanted the Hub to [integrate with other MyUSA-authenticated services](https://github.com/18F/hub/pull/211) that serve JSON API endpoints. For that we needed the MyUSA access token, which oauth2\_proxy originally threw away. So I added [access token pass-through](https://github.com/bitly/google_auth_proxy/pull/80) to oauth2\_proxy to make the integration possible, and [cleaned it up later](https://github.com/bitly/google_auth_proxy/pull/81).
