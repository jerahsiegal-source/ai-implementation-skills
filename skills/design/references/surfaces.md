# Surfaces

Same taste, different job. Read only the section that matches the screen being built.

## Landing page
- Job: make one idea land and get one action.
- Hero states the value in plain words, with the real product or a real visual, not a stock gradient.
- One primary call to action, repeated at most twice. Three to five sections, each with one point.
- Density: airy. This is where the bold move lives.
- Avoid: feature-card grids by default, vague slogans, fake logos and testimonials.

## App dashboard
- Job: let a returning user see what changed and act on it.
- Top row: the few numbers or statuses that decide what to do next. Then the work itself.
- Status by icon plus word. Problems rise to the top on their own.
- Density: dense but ordered. Consistent grid, aligned numbers, quiet chrome.
- Avoid: decorative hero areas, giant whitespace, one metric per huge card.

## Form or setup flow
- Job: get the user from start to done with the fewest decisions.
- Group related fields, show progress for multi-step flows, use sensible defaults.
- Hide advanced options behind a toggle. Validate inline with a fix, not just an error.
- One primary button per step, placed where the eye ends.
- Avoid: walls of fields, unexplained jargon, losing input on errors.

## Results and analytics
- Job: answer "what happened and what should I do?".
- Lead with the finding in a sentence, then the evidence (charts, tables), then the raw detail.
- Make comparisons easy: same scales, side-by-side, deltas shown.
- Avoid: dashboards of charts with no takeaway.

## HTML report
- Job: let someone skim in 5 seconds and dig in when they want to.
- Verdict and key numbers first, then scannable sections, then detail behind clicks.
- A contents rail or tabs for long reports. Sources linked next to claims.
- Avoid: long scrolling prose, everything open at once.

## Component mockup
- Job: refine one piece in isolation.
- Show it in real context and in every state (default, hover, focus, disabled, error, empty, loading).
- Use the project tokens so it drops straight in.

## Slides
- Job: one point per slide, readable from across the room.
- Headline states the takeaway. One visual per slide. Detail in notes or behind a "show details" toggle.
- Avoid: bullet walls, tiny charts, more than about 30 words per slide.
